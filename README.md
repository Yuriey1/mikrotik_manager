# MikroTik Device Manager

Веб-приложение для управления устройствами **MikroTik RouterOS** через API. Позволяет управлять DHCP-абонентами, деревом очередей, доступом в интернет и ARP-таблицей. Список устройств загружается из **NetBox**. Поддерживает интеграцию с **Matrix** для приёма заявок на подключение абонентов.

## Возможности

### Управление абонентами
- Просмотр и управление DHCP-абонентами (добавление, редактирование, удаление)
- Визуализация прохождения трафика от канала до абонента через дерево очередей
- Назначение абонентов в очереди (Simple Queues) с подбором подходящей очереди
- Управление доступом в интернет (firewall address-list `internet_access`)
- Замена MAC-адреса абонента (по IP или вручную)
- Просмотр дерева очередей с иерархией и статистикой
- Поиск свободных IP в DHCP-пулах
- Очистка устаревших IP с фильтром по `last-seen` (30/60/90/180/365 дней, never, все)
- Интеграция с NetBox — список устройств, роли, сайты

### Matrix-интеграция
- Приём заявок на подключение из комнаты Matrix (Element)
- Автоматический парсинг заявок (regex) — ФИО, должность, организация, площадка, IP, MAC
- Мульти-заявки — разбивка одного сообщения на несколько абонентов
- LLM-парсинг через DeepSeek API (опционально, режимы hybrid/llm)
- Классификация сообщений (заявка / не заявка)
- Верификация сессии через SAS (эмодзи) — авто-подтверждение
- Отображение эмодзи в профиле при верификации

### Пользователи и сессии
- Многопользовательская система (SQLite, таблицы `users.db`)
- Регистрация и вход по логину/паролю (bcrypt)
- Индивидуальные учётные данные MikroTik для каждого пользователя
- Профиль пользователя: Matrix-токен, LLM-ключ, смена пароля
- Авто-очистка сессий (TTL 2 часа)

## Требования

- Python 3.10+
- Доступ до MikroTik API (порт 8728)
- Настроенный NetBox (опционально, для списка устройств)
- `matrix-nio` для интеграции с Matrix
- `bcrypt` для аутентификации (опционально, fallback на SHA-256)

## Установка

```bash
git clone <repo-url>
cd mikrotik_manager
pip install -r requirements.txt
```

## Запуск

```bash
python3 main.py --port 8090 --host 0.0.0.0
```

Параметры:
- `--port`, `-p` — порт (по умолчанию 8090)
- `--host` — хост для привязки (по умолчанию 0.0.0.0)

Откройте в браузере `http://<IP-сервера>:8090`.

### Первый запуск

1. Зарегистрируйте пользователя через форму входа (admin создаётся автоматически при первом запуске)
2. В профиле настройте Matrix: включите интеграцию, укажите пользователя, комнату, токен
3. Подключитесь к устройству MikroTik через боковую панель
4. Для LLM-парсинга: добавьте API-ключ DeepSeek в профиле

## Настройка NetBox

1. В веб-интерфейсе нажмите ⚙️ в панели «Устройства»
2. Укажите URL NetBox и API-токен
3. Нажмите «Проверить», затем «Сохранить»

Устройства фильтруются по производителю `Mikrotik` и наличию основного IP.

## Верификация сессии Matrix (SAS)

При первом подключении бота к Matrix требуется верификация устройства:

1. В Element: Настройки → Сессии → найти устройство бота → «Заверить сеанс»
2. Бот автоматически принимает верификацию и подтверждает эмодзи
3. Эмодзи отображаются в профиле (секция «Запрос верификации»)
4. После завершения в профиле появляется статус 🟢 «Верифицирован»

Если верификация не проходит (`key_mismatch`):
1. Удалите старые сессии mikrotik-manager в Element
2. В профиле: сбросьте токен → введите пароль Matrix → сохраните
3. Повторите верификацию с новым device_id

## API

### GET

| Эндпоинт | Назначение |
|----------|-----------|
| `/api/devices` | Список устройств из NetBox |
| `/api/connect` | Подключение к MikroTik |
| `/api/disconnect` | Отключение от устройства |
| `/api/sync` | Все данные одним запросом (очереди, абоненты, каналы, интерфейсы) |
| `/api/tree` | Дерево очередей |
| `/api/stats` | Статистика очередей |
| `/api/find_queues` | Поиск очередей по IP |
| `/api/free_ips` | Свободные IP в DHCP-пулах |
| `/api/internet_access` | Список IP с доступом в интернет |
| `/api/analyze_channels` | Анализ каналов трафика |
| `/api/check_mac` | Проверка занятости MAC |
| `/api/check_ip` | Принадлежность IP к сетям MikroTik |
| `/api/find_dhcp_lease` | Поиск DHCP-лизинга по IP |
| `/api/dhcp_pools` | Список DHCP-пулов |
| `/api/dhcp_subscribers` | Список DHCP-абонентов |
| `/api/netbox/config` | Текущие настройки NetBox |
| `/api/netbox/test` | Проверка соединения с NetBox |
| `/api/old_leases` | Устаревшие DHCP-лизинги (age, include_never, show_all) |
| `/api/netbox/site_for_ip` | Определение площадки по IP через NetBox |
| `/api/device_credentials` | Учётные данные MikroTik для пользователя |
| `/api/users` | Список пользователей (admin) |
| `/api/profile` | Профиль текущего пользователя |

## Режимы парсинга Matrix-заявок

| Режим | Описание |
|-------|----------|
| `regex` | Regex-парсер (9/9 тестов). Извлекает: ФИО, должность, организация, площадка, IP, MAC. Без LLM. |
| `hybrid` | LLM + regex fallback. При ошибке LLM использует regex. |
| `llm` | Только LLM-парсинг (DeepSeek API). |

### Классификация (этап 1)

При включении LLM можно активировать предварительную классификацию — определяет, является ли сообщение заявкой, перед парсингом. Снижает нагрузку на LLM API.

## Логирование

Логи пишутся в два потока одновременно:
- **Консоль** — уровень INFO (при запуске вручную)
- **`mikrotik_manager.log`** — уровень DEBUG (все сообщения, включая отладочные)

Формат: `ЧЧ:ММ:СС  LEVEL   сообщение`

## Файлы с чувствительными данными

Следующие файлы не должны попадать в репозиторий (добавлены в `.gitignore`):

- `plugins/matrix_integration/_matrix_store/` — ключи шифрования Matrix
